# GPT Image / 已确认的 OpenAI 图像入口

核验日期：2026-10-12。适用路由：`image`。来源类型：官方文档；下列骨架与例子由 HEX 整理。未进行本次模型实图对照，不标为质量验证通过。

## 版本与入口

官方 Image prompting 当前覆盖 GPT Image 2.5 Flare、Sunburst，并保留 GPT Image 2 等旧版参考。API ID 分别为 `gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`、`gpt-image-2`。保留用户选定型号；不能以当前文档主推版本替换用户的已验证工作流。[1][2]

`image` 适用于 GPT Image 及已由用户选择、已确认由 OpenAI 提供的内置图像入口；不能把任意宿主的内置生图服务映射到这里。WorkBuddy、豆包工作等未公开后端时只记录已选服务与未知后端，使用 unknown-service.md 的通用指导。内置工具没有公开底层版本或模型参数时如实记未知，不由 “Image 2.5” 昵称推断后端，也不把独立 API 字段塞给内置工具。用户未选择模型时先问，不能因为此工具可用就自动选它。

## 官方要点

- 交代要得到的图像、主体、构图、风格和重要限制；复杂要求可分区，短请求无需固定格式。[1]
- 将抽象情绪落实为能看见的空间、光色、材质和动作关系。镜头数值是外观线索，不保证精确物理模拟。[1]
- 必要文字逐字给出，并说明位置和层级；多参考逐一明确用途。[1]
- 编辑明确这次改变什么、什么要保留；连续编辑传入实际上一张输出，并重述关键约束。[1]
- 模型、质量、尺寸、透明背景等属于请求设置，和提示正文分开；只能使用当前入口开放的字段。[2]

## HEX 新建骨架

```text
生成用于[已确认用途]的[图像类型/媒介]。
[主要主体]正在[动作/状态]；[必要次要元素]与主体形成[明确关系]。
以[观看位置、景别和主次]组织画面，[必须的相对位置或留白]。
[与表达有关的材质、光源、颜色及背景层级]。
画内文字：[逐字内容及位置；没有文字需求则省略本行]。
必须满足：[少量关键关系和限制]。
```

这些段落按任务合并或省略，不自动把绘画改成摄影，不为动作说明强行露出用户没要求入镜的身体部位。

## 参考图与编辑骨架

```text
以图1为本次编辑底图。只将[实际目标区域/属性]改成[可观察的新状态]。
图2仅提供[身份/材质/色彩等指定职责；无图2则省略]。
保留[用户要求保持的身份、几何、构图、文字或光线]。
让修改处的[边缘、接触、光照和材质关系]与底图协调。
```

实际图片编号必须与提交顺序一致。身份图、风格图和评价图不能互换；只有已允许的生成输入才上传。完整重构与局部修改是不同范围，不能借编辑骨架扩大授权。

## 简短例子

以下仅示范已确认 brief 的写法，不作为默认审美方向。

```text
制作一张陶瓷展海报。乳白陶壶位于右下，壶嘴指向画面中央，左上保留清楚的标题区域。温灰纸面背景上只有一片柔和的侧光投影。标题逐字写“器物之间”，标题下写“当代陶瓷展”；两段文字各出现一次，字级清楚。
```

编辑同一图时可写：“仅将陶壶釉色改为深青绿；保留壶形、壶嘴方向、原构图、标题原文及纸面光影。”这种保留指令不能单独保证非目标像素完全不变。

## 设置与边界

- API 的参数与内置工具 schema 分别读取。API 中的 `background`、`quality`、`size` 不等于内置工具具有同名参数。[2]
- 已确认的 OpenAI 内置工具要求透明背景时使用其真实透明开关；编辑保留已有透明状态，除非用户要求变化。不得把棋盘格图片当成透明文件。
- 旧 `input_fidelity` 等参数不能跨版本直接复制；用户指定旧版时查对应版本参考。[2]
- 不添加 Midjourney 的 `--sref`、CLIP 权重括号或另一模型的 JSON 包装并声称原生支持。
- 需要逐像素保留时必须依靠实际编辑/合成工作流并核验输出。文字正确、主体保留和整体表达仍需实际看图检查。
- 本卡语言为 HEX 中文工作说明；可按用户交付需要写中文或英文，不宣称某语言天然更优。
