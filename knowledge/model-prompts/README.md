# HEX 模型提示词资料

核验日期：2026-10-12。这里缓存官方提示建议、适用边界，以及 HEX 据此整理的写作骨架。骨架是编译方法，不是固定场景、强制语法或效果保证。各模型档案仍为 `experimental`；资料核验不等于实图通过。

## 先确定这次给哪个模型使用

1. 读取本题原话、已回答上下文和已有任务中的模型选择。明确过的沿用，不重问；其它项目或历史偏好不自动迁入。
2. 新建图片、编辑图片和只写提示词，都需要明确目标模型。用户没说、当前任务也没有已确认选择时，先问“这次准备给哪个模型使用？”不能按可用工具、题材或旧默认补一个模型。
3. “你选模型”允许宿主在本题范围内选择并说明依据；“自由发挥画面”“按 HEX 全流程”不自动等于委托模型选择。选择来源与宿主判断分开保存。
4. 只说平台或家族名、且不同版本/入口会改变写法时，问实际名称或使用入口。用户明确选择当前宿主内置生图时已经选定服务路线；只有已确认是 OpenAI 图像入口才记为 `image`。其它宿主未公开的内置后端保持未知，不借熟悉模型的 target，无需逼用户猜 API ID；按 [未知服务指导](unknown-service.md) 处理。
5. 缺答案时保留待确认，不把沉默写成同意。可继续与选型无关的分析，但不冻结模型正文或调用默认模型。只做素材搜集、架构讨论和源码维护无需询问生图模型。

先读本索引，再只读对应卡。程序在新任务中按明确的 `brief.targets` 读取卡并保存快照；编译输入同时提供该目标的档案和卡内容。任务中途更换指南须明确重新准备相关上下文，不能静默改变已有冻结正文。

## 从已确认需求到模型正文

顺序为：需求分析 → 必要问询 → 素材研究 → 判断取舍 → 模型编译。先确定用户要表达的关系和限制，再把参考中实际看见的可迁移关系转成方案；模型卡只决定如何清楚表达方案，不能替用户决定画面含义。

编译时保留用途、主次、数量、身份、精确文字、参考职责和修改范围。选择与实际模式相符的骨架，只写本题需要的段落；不为凑长度添道具、人物、摄影参数或质量词。用户只要短提示时压缩非关键描述，保留约束。

交付包含准确的模型/版本与模式、可复制正文、实际需要的独立设置或参考图说明。普通对话不输出管线 JSON；只有真实入口要求该协议时才给结构化请求。提示词正文不混入研究链接、HEX 内部字段和另一模型的参数语法。

## 何时复查资料

- 已选型号和模式在缓存范围内，且没有接口冲突时，直接使用卡中的写法；不每题重搜通用提示教程。
- 用户明确要求最新信息，选了未覆盖版本/模式，实际工具拒绝字段，或来源出现矛盾时，只补查相关官方页面。
- 要依赖会变化的 API 参数、可用型号或当前版本事实时，核对实际入口和资料日期；到复查期就复查这部分，不把旧事实说成当前已验证。稳定的构图/表达方法可继续复用。
- 更新卡时记录日期、变化与来源，并提升相应模型档案版本；新资料不静默覆盖旧任务证据。

官方文档、官方仓库优先。社区方法只有能追溯到同版本原文或有可检查的结果时才补充；作者自评、收藏数和格式测试不能证明画质。未经独立结果核验的“高好评”说法保持候选，不写成 HEX 的默认优势。
