# Nano / Gemini Image 提示词指南

核验日期：2026-10-12。状态：experimental，仅完成官方资料核验，未验证本卡的成图收益。
适用：用户明确选择的 Gemini 原生图像型号；按新建、参考生成、编辑读取相应部分。
本卡不确定用户实际帐号、界面或工具是否可用，不据此派发生成。

## 1. 先确认实际型号

| 用户/官方名称 | 官方模型标识 | 本卡边界 |
| --- | --- | --- |
| Nano Banana Pro | `gemini-3-pro-image` | Pro 的参考、复杂编辑能力不能套给 Lite |
| Nano Banana 2.1 | `gemini-nano-banana-2.1` | 独立于 Pro 和上一代 2 |
| Nano Banana 2 | `gemini-3.1-flash-image` | 不静默改为 2.1 |
| Nano Banana 2 Lite | `gemini-3.1-flash-lite-image` | 官方说明不以多参考或多轮连续编辑为优化目标 |
| 旧 Nano Banana | `gemini-2.5-flash-image` | 保留旧版身份，不把系列俗称自动映射到它 |

型号未明确时问：“你这次用哪个 Nano 版本？给我界面上的模型名即可。”
已有本题的明确选择则复用；用户明确委托选择时，说明所选型号与理由。
Gemini App、AI Studio、API 和第三方入口的能力可能不同；参考数量与输出规格按实际入口确认。

## 2. 官方建议

- 用清楚的主体、动作、场景、构图和风格描述目标；用途有助于模型理解设计意图。来源：[G1]、[G2]。
- 专业摄影任务可描述光源、景别、视角及表面表现；只补与本题有关的细节。来源：[G2]、[G3]。
- 多图输入清楚分配每张图的职责，例如身份、姿势、背景或风格。来源：[G3]。
- 所需文字给出准确原文，并说明字形、位置和层级。来源：[G2]、[G3]。
- 改图直接说明具体变化；后续对话可继续调整，保留已认可内容。来源：[G1]。
- 优先描述目标状态；复杂画面可分步说明，避免无关排除词累积。来源：[G1]。

## 3. HEX 整理的可复制骨架

以下为 HEX 编排的写作顺序，不是官方强制语法；删除无关槽位。

### 新建

```text
为[用途]创作一张[画幅与媒介]。[主体与动作]位于[场景]，[构图与视觉主次]。光线呈现[具体关系]，材质呈现[可见特征]，色彩采用[本题方案]。如需文字，准确呈现“[原文]”，位于[位置]，采用[字形与层级]。
```

### 参考生成

```text
图1提供[主体身份/结构]，图2只提供[姿势/风格/材质]，图3提供[环境]。将[主体]放在[目标场景与构图]，保留[本题重要特征]，让[光线、尺度与接触关系]统一。
```

### 编辑已有图

```text
编辑图1中的[明确对象/区域]，将[原状态]改为[目标状态]。保留[构图、位置、身份及本题保护项]。图2仅提供[允许借用的属性]。让修改后的[光影/材质]与原图保持连贯。
```

### 继续上一轮

```text
基于上一张结果，仅把[已有问题]调整为[可见目标]，保留[已认可内容]。
```

## 4. HEX 示例

下面仅演示编辑写法，不作为固定题材或风格：

```text
编辑图1，将蓝色陶瓷杯改为暖白色釉面。保留杯形、把手位置、桌面和构图，让釉面的反光沿用原图左侧窗光。
```

## 5. 避免混用

- 不把“Nano”自动当作 Pro，也不凭历史偏好决定本次型号。
- 不把 API 参考图上限或分辨率推广到所有帐号和第三方入口。
- 不混入 Midjourney 参数、Stable Diffusion 权重语法或无依据采样值。
- 提示词里的“4K”不代替实际输出设置；尺寸以工具输入和回执核对。
- 只取材质的参考图不能同时接管主体身份；图片职责保持到最终输入。
- 保留指令表达目标，不承诺像素、结构或细小文字绝对无误。
- 骨架不为局部编辑补出新场景；也不把官方建议误写成用户要求。
