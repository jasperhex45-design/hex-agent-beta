# 单车摄影候选入口

本 Skill 保留单车摄影的身份、参考职责、设计与输入冻结方法，不把方法存在称为已通过实图验收。执行与完成以当前工程 `AGENTS.md`、`CODEX_START.md` 的统一流程为准。已有任务先 `status` / `resume`，不改旧配置、预算或用户反馈，不恢复已停止实验；新任务不能因提示词已交或首图已返回就跳过适用检查。

## 新任务

用户用自然语言表达目标；“汽车生活向”也足以启动理解，不要求先给车辆素材。先判断想表达的生活感是否清楚，模糊时用 Copilot 问感受、用途或偏好，再找图，不预设为露营或给固定风格菜单。宿主负责文件和技术取舍，沿用当前 Brief、Need、Plan、Solution，不新增问卷或第二套合同。用户未指定的场景、车型、人物关系和光线保持提案，不能提前锁成共同需求。

```text
python -m hex_agent car prepare --brief INPUT --sources SOURCES --out RUN --deliverable-kind image
```

上方示例为成图，用户只要提示词时填写 `--deliverable-kind prompt_only`，真实局部编辑填写 `local_edit`；不让用户填写内部类型。公共入口自动启用完整流程要求，现有汽车知识策略保持。缺省目标为 Seedream；用户明确指定 Image 则在 Brief 中保留 `targets=["image"]`。未接入的模型明确说明，不偷偷替换。本命令不检查在线账户或授予权限。工具能力在创建时绑定，观察、需求更新和设计完成后再登记真实生成授权。

宿主按原话填写 Brief 的 `vehicle_identity`：未指定现实车型或具体车辆的新创作可用 `open`，无须身份图；要求保持具体车辆或现实车型用 `preserve`，至少一张当前车辆 identity 图。默认仍为 `preserve`，已有任务不静默改写。`open` 只适用于 `create`，不能用于有身份要求、身份待澄清或真实父图编辑的任务。身份照片决定车型事实，摄影案例提供方法；无身份照片不等于不需要研究摄影，也不应退回通用流程绕开汽车方法。

Windows 统一入口给新任务选择 `car-photography-knowledge-v1`，最多3次本地语义查询、6张候选，继续使用原汽车设计方法与全部身份/范围/冻结限制。读取 RUN 的 `HOST_TASK.md`、`creation-instructions.md`、`packet.json`、必要原图和目标模型输入；不另写第二套通用方案。候选沿原 core_knowledge_ids/checks 采用，可零采用。原 car-photography-v1 和旧任务不自动升级。多图身份参考不等于锁机位；单图编辑按用户明确范围保留机位。商业和艺术题分别设计，不固定城市、车色、曝光或构图比例。

开放车型的新任务在没有显式知识配置时也启用汽车摄影的有限本地检索；当前环境的真实检索方式与降级写入记录，不把文本命中称为看过参考。只采用适用的方法，不把候选库或历史反馈当固定审美答案。

宿主整理 Need 后用 `refresh`，按 `visual_research` 选择路线。开放目标、明确研究请求或已拒绝方向走 `study`，按 [设计研究](../liu-aesthetic-agent/references/design-study.md) 主动找并看真实摄影案例，说明采用与舍弃如何改变人车关系、瞬间、主次或光线。不确定就扩展不同来源；没有合适案例或偏好未解决时用 Copilot 共创。按实际依据选一个最终方案，不凑固定方向或参考数量，无须分别生图。用户已指定视觉方向或有界局部修改可基于真实来源说明免研究理由；明确禁止研究可据原话选 `user_waived`，不称已研究。宿主自己的初稿不算免研究依据。

必要素材实际看图，按原接口 `observe`，用 `choices.reference_uses` 绑定观察、取舍与检查。完成 Plan 后用原 `prepare-compilation --target ... --tool ...` 编写一个完整目标模型提示词，再执行原 `preflight`。不要将完整历史审计或全部私人图库注入创作；研究参考可保持 `evaluation_only`，图像可观察不等于可上传。

## 实发输入预览

```text
python -m liu_agent.car_photography preview --run RUN --solution SOLUTION --resolution 2K
```

`2K` 只是命令示例，实际分辨率按本题确定；Image 路线不传小云雀的 resolution/ratio。返回正文、模型参数、素材顺序与摘要，以及原稿和编译正文是否一致。预览不会派发、占用额度或登记授权，也不替代实际工具可用性检查。

复现已有有效正文时加 `--expected-prompt TEXT_FILE`；完全一致才返回 0，不一致返回 3，错误返回 2。比较包含空白和换行，不自动修补基线。新 `model_adaptation` 任务的 `row.text` 必须已含完整正文；程序检查对应约束片段，不追加原始硬锁。仅历史无适配合同的任务保留旧拼接行为。应检查差异，不删除约束校验；没有证据不声称历史输入已复现。

## 冻结最终输入

新任务在预览核对后执行 `python -m liu_agent.car_photography freeze-input --run RUN --solution SOLUTION --resolution 2K`；Image 不传 resolution。仅提示词任务完成当前统一检查后交付 `finalized-prompt.txt`，不强迫生成图片。普通新创作允许合法新正文；基线复现同时传 `--expected-prompt TEXT_FILE`，任何正文差异都阻断，已经冻结的基线不能重冻成其它正文、模型、顺序或实参。

`prepared-request.json` 只保存待派发输入，不是新预算或执行账本。新任务带 request_input_version=1；dispatch 强制重核需求、方案与完整输入并消费冻结结果，执行器只消费 dispatch 实参。跳过冻结、正文/模型/素材/分辨率改变都不能占用调用。旧任务不自动迁移；已有 pending/unknown 仍恢复原请求。

完整正文由宿主在冻结前编写并落实全部约束；新适配任务不依赖程序隐式补全。预览明确显示原稿差异，最终文件原样保留换行。硬事实检查继续保留；片段存在及模型的语义自查都不是等义证明。

## 真实执行与反馈

先完成完整提示词；用户需要成图且已有本题有效生成与素材许可时，输入冻结后直接继续 `authorize-generation → dispatch → execute-pippit / 实际工具 → record-result → 适用检查 → 统一完成门禁`，不等待用户再确认每个内部步骤。仅提示词任务完成相应检查后交付。`dispatch` 参数必须与核对过的最终输入一致。内置 Image 按本题有效宿主分工执行，小云雀按已有 execute/query 入口执行；不要用预览调用模型。

可以先展示真实原图预览，同时继续本题文件、文字和实际看图检查；预览不代表完整流程已完成。记录接受/拒绝时绑定真实图；相对更好不等于可交付。明确续改时使用现有父图、反馈、`refresh --out` 与原预算关联，保持正确部分，失败退回原图。unknown/pending 只查询原请求，不重复生成。

使用 `CODEX_START.md` 中当前统一检查与完成入口，确认报告绑定本题实际候选。只有本题明确画内文字要求才派生 OCR 检查；没有文字需求不加载 OCR。车型身份、主体位置、车漆反射、环境融合及构图表现按本题要求实际看图判断，文件或 OCR 通过不能代替。检查失败时保留证据，沿现有许可有限修复或说明具体阻塞，不能直接跳到已完成。

工程通过、输入一致、真实图返回、用户接受分别陈述。车型、数量、结构和文件合格与生活感、视觉主次及表达效果分开评价，基础检查满分不称审美满分；整体比较不利时不能只挑有利分项宣称胜出。测试不能证明光影更好或审美提高。
