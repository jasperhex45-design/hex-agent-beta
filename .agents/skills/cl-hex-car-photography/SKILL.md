# HEX 单车外观方法

本 Skill 只补汽车方法及专属输入控制。旧名直接触发时先按 [统一入口](../../../docs/RUNTIME.md) 理解需求、准备或恢复任务；已有 HEX 任务沿当前阶段继续，不另建合同。通用研究、权限、执行、反馈和完成只使用统一流程。

## 身份与模型选择

新单车外观任务使用 `car prepare`。按真实用户来源选择 Brief 的 `vehicle_identity`：

- 未指定现实车型或具体车辆的新创作用 `open`，无须身份图；只适用于 `create`。
- 需要保持具体车辆/现实车型用 `preserve`，至少提供一张当前车辆 identity 图。它仍是程序缺省值；身份待澄清或真实父图编辑不能改为 `open` 绕过素材要求。

身份照片决定车型事实，摄影案例提供方法，二者不能替代。多视图保身份不等于锁机位；用户锁定的单图编辑机位、比例、轮心与保留项按本题保持。无身份照片的开放创作仍需适用研究，不因此退回通用入口。

当前汽车专用执行入口只接受单个 `seedream` 或 `image` 目标；`nano` 只用于 `--deliverable-kind prompt_only`（只交付提示词，写法见 [汽车 × Nano](../hex-car-nano/SKILL.md)）。程序不代选。先核对本题原话、已有回答或明确模型选择委托，按真实选择填写 `targets`；没有依据时必须先问用哪个模型，已有选型不重问。不能因适配器可用或档案存在替用户选型；其它模型的提示词沿通用编译入口与本目标指南处理，不强迫用户换模型。只要提示词或无生图工具时，按统一入口从开始选 `prompt_only`，不强迫调用模型。

## 摄影决定

根据真实意图与参考决定人车关系、瞬间、主次、空间、光影和车漆响应；不固定城市、车色、曝光、机位或构图比例。生活向需求不预设为露营。只控制使本题成立的必要关系，保留正确部分和允许变化的细节。

开放研究读取 [设计研究](../liu-aesthetic-agent/references/design-study.md)，说明每项实见方法如何改变当前摄影决定，不能只换车型或颜色凑方向。身份准确、反射可读和基础结构合格，与生活感及表达效果分别判断。

当前汽车知识策略最多 3 次本地查询、6 条候选，真实 Need 后才检索，可零采用；记录实际 backend 与降级，不把文本命中称为看图。`open` 且未指定知识配置时也有有限本地检索；Windows 环境与原生模型按 [运行环境](../../../docs/WINDOWS_RUNTIME.md) 核验，不把旧安装记录当新机器事实。

## 预览与冻结最终输入

完成当前模型编译和 preflight 后，依次预览与冻结：

```text
PY ENTRY car preview --run RUN --solution SOLUTION
PY ENTRY car freeze-input --run RUN --solution SOLUTION
```

`PY/ENTRY` 沿用主入口真实路径。Seedream 的比例与分辨率依本题添加对应 `--ratio/--resolution`；Image 不传小云雀专用参数。预览展示完整正文、模型、实参、素材顺序与摘要，不调用模型或授予额度。

基线复现才加 `--expected-prompt TEXT_FILE`：逐字比较包含空白和换行，相同返回 0、不同返回 3、错误返回 2，不自动修补差异后声称复现。新 `model_adaptation` 的 `row.text` 必须含完整正文；程序校验不代替语义等价，也不隐式追加硬锁。

`prepared-request.json` 保存冻结输入；dispatch 重核需求、方案、正文、素材顺序、模型及必要参数并消费它。冻结后不得改实参冒充同一调用；需要变化沿关联版本接续。只有旧无适配合同任务保留原拼接行为，不改写其输入。

冻结后回到统一入口交付目标提示词，或真实生成、保存原图并完成适用检查。`finalized-prompt.txt` 是提示词产物，图片效果以实际结果为准。
