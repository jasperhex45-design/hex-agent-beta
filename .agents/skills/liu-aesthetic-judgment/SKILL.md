# 用图像证据做取舍

目标是在鲜明甚至极致的表达中找到平衡，保住真正有作用的关系。均衡不等于面积、清晰度、强度或完成度的平均；极致也可以极安静、极疏或局部极密。风格库保存真实图与观察，本 Skill 保存主动发现关系和作取舍的方法；代码验证通过不代表审美通过。

## 1. 先确定用户到底要改什么

读本轮原始消息、需求交接、主参考和当前候选，沿用已确认的意图与修改范围，不自行重写一套用户目标。先据实际图像说明最先抓住人的是什么，它与其余画面共同带来什么感受；把可见事实与自己的解释分开。再明确本次希望保留或改变的感受，以及支持它的整体关系，写入现有 expression / intent_claims。姿态、位置、空白和光色由此选择，不先选偏置、留白或相反方向，再贴上情绪名称。表达可以由形式本身承担，不必有故事；参考分析与自拟设计均不能冒充用户认可原因。

区分改动对象、区域和程度。比如“鳞片感”可能指全图碎纹重复，也可能只指鱼身。能从原图及上下文判断就写明解释；方向含糊时先用 Copilot 问最影响表达的感受、用途或偏好，再找图和设计。问题不预设封闭风格菜单，不让用户选技术参数；不得将猜测升级为 must_keep 或永久偏好。

保留用户指定主参考的优先级。辅助参考各解决明确问题；“杂揉”不要求平均混合所有图片。返修先找真正承载表达的关系，再定最多两个修复问题；保留这些关系的作用，不是让所有局部原封不动。

## 2. 根据判断寻找真实案例

先读当前 packet 的 `visual_decision_policy`。production-baseline / visual-relations-v1 关闭自动经验检索，只使用当前任务必要参考和显式研究，不手动读旧库绕过。只有无该 policy 的 legacy 合同才沿用其已保存的 style-context 设置；只读本轮命中卡，零命中或零采用都允许。

打开拟采用的 source_images 原图。图像事实、你的解释、迁移假设、用户明确选择须分开；旧卡写过“已看图”不等于本轮看过。不能只凭摘要重述视觉原因。

本地图库只是当前可用来源之一，不能穷尽风格。宿主按目标主动搜索、实际看作品并判断适用性；不确定就分批扩展不同作者、场景或表现方法，不受固定参考总数或两个方向配额限制。当前清单只保留对决定有用的参考与真实观察，遵守其容量和授权。找不到合适案例或需要用户偏好才能取舍时，用 Copilot 说明实见差异与未决问题；不强行选择，也不把搜索和看图留给用户。

主动找原图最有力量的关系，再找它靠什么成立：大小悬殊的形、密集与空场、偏置与回引、精确与粗粝可能相互承托，也可能有意冲撞。指出具体区域；若把它们都修得相近，会损失什么？据图提出解释，不等用户再给美学口号，也不预设每张图都必须靠对比。

当前生产任务用 `add-reference` 接入必要原图，再通过 observe 记录实际观察；`library attach-curated` 仅在 legacy 合同允许时使用。设计中的 reference_uses 引用同图观察，并连接到对应 check。默认 evaluation_only，只供判断；分析许可不自动授予生图参考用途。不同题材只借适用且允许迁移的结构。

相关历史 A/B 仅证明该对图的相对选择。先核实原图与任务范围，不能由“第一张更好”推导所有任务都要更淡、更少线或同一颜色。不得自动修改长期偏好。

## 3. 提炼因果关系，不堆风格词

按“表达 → 观看关系 → 具体动作 → 承托或对抗 → 代价”写入原有 choices 的 action / cooperation / tradeoff。先把有力量的主张做足，再检查关系与用途；多个强元素可以成立，只要它们相互需要。精确、破碎、偏斜、粗粝和留白按作用分配，不能用处处精致或全面简化替代判断。

不完美先按视觉意图与实际用途判断。生成前在 checks.expected 写清允许的变化及作用，在 failure 写清损害表达或功能的界限；不要只把取舍写在 tradeoff 而漏出固定验收标准。身份、指定文字、操作范围等明确要求仍须满足。旧标准若确实不符合新目标，在旧记录之外保存新方案与生成前标准；尚未生成时可修正需求，不能出图后降低标准。图像运行记录的调整不要求更换 Codex 会话。

例如本次目标是“凌厉且有水墨意味”，可由关键手势的明确转折与衣袖、背景相接的中间调构成张力；若目标是密集线势的压迫，极密线群也可能是主体。根据当前表达决定精确、可辨或省略的区域，不要求每张图都凑齐三种层级。线条与色面各承担什么必须具体。

保留过渡区。虚可以来自边缘消失、信息减少、层次接近；实可以只落在一个目光、手势或转折。全图模糊、平均颗粒、重复碎纹、简单减细节都不自动等于意象。以上是当前题材的候选动作，不是通用美学公式。

黄金分割、三分法、流派或艺术结构只在解决当前问题时采用；位置规则本身不能证明美。不把艺术家、流派名代替可见动作。

跨题材借用、表达与用途冲突或同一技法反复失效时，读 [迁移与返修反例](references/transfer-and-revision.md)，检查哪些不完美有效、哪些伤害了当前用途。

## 4. 提示词只做一轮有限检查

核对：最有力的表达是否被做足，还是在折中中变平；承托或对抗是否具体；用途和硬约束是否满足；允许的取舍是否进入固定标准。精简只删除无作用的内容；有作用的密度、夸张或瑕疵应保留。修正最多两个实质问题后编译，不循环自评。

表达转译较大或用户已否决方向时，在本轮检查中核对：动作、材质和构图安排都实现后，所承诺的感受是否仍可能缺席？若方案本身缺少支持这种感受的依据，回到理解、参考或设计；若候选基本照方案执行仍显空洞，不能默认归因于姿态不够用力或提示词不够强。只有具体执行偏差确实削弱了已有依据的表达，才按局部问题修复。保留已经成立的技术项，不改写冻结标准，也不把讲故事、强对比或填满画面当作通用答案。

使用现有模型适配器。新版本所有choices都须进入最终prompt，普通参考不依赖审美卡；英文按choice_id填写choice_translations，动作与cooperation都要等义。采用卡片时仍填写translated_aesthetic_relations，复读中英文关键关系是否一致。字段齐全只证明覆盖，跨模型效果仍待实图验证。

## 5. 看图后比较收益和损失

沿同一原始目标并排看旧图与新图。先查身份、机位、文字和修改范围，再查注意顺序、动作关系、虚实过渡和技法分工。每个结论指出区域与可见现象。

既写表达与用途哪里改善，也写丢了什么：例如碎纹减少，但衣袖到背景的中间层被切断；也可能粗粝增加，却让动作更有力度且仍可读。预先允许的不完美不自动记退步，真实功能损失也不包装成艺术。不能因为新图更整齐、简洁、无瑕或更像辅参考就选新图。差异不明确时保留旧版；用户最终选择优先。

结合generation_evidence核对真实prompt、原方案和有序输入，不把方案已执行误判为表达成立。把必须保留的具体区域关系写入Eval.preserve，把最多两个修复动作写入changes，并通过revision_targets绑定有图像证据的not_met标准；两者都会进入实际返修提示词。没有具体可见问题或只有unknown/uncertain时不自行重画。用户另要新方向或变体时用关联需求版本处理，保留原预算，不伪装成必要修复。

成对报告 evidence 同时写收益和代价，regressions 只记录尚未解决、未被当前明确目标接受的退步。已被目标接受的必要取舍仍在 evidence 说明；不能为了选新版把尚存损失删掉。B 有未解决退步、原来通过的检查变差，或比较本身 uncertain 时，运行时保留 A 供比较并标记取舍不确定；不把单图 ready_for_user 当成净改善证明。两图及各自方案都保留。

用户否决整个方向时，保留原 Eval 与否决事实，回到需求、参考作用和设计取舍。模型提出的可能原因另标假设；不能继续把同一方向的表面抛光称为解决了否决，也不能借换目录重试或重置已用生成预算。

单图接受或否决用 `record-feedback --run ... --decision accepted_by_user|rejected_by_user --user-quote ... --source ... --sources ... --source-id ...`，按反馈来源接口（`record-feedback --help`）将实际用户消息、明确选择及当前图片绑定，快照独立追加，不改冻结需求。接受仅适用于选中图，机器复查与任务整体验收各自保留。`single_feedback_roots` 中相关任务的有效记录才参与后续召回。不要为单图反馈伪造另一张图或成对选择。

对用户解释复查时读取实时 `status --format human`，以其证据等级表述实际执行范围。具体诊断按“看到的现象 → 观感影响 → 当前需求或参考 → 本轮动作 → 原标准中的成功条件”说明；引用 `presentation.diagnosis` 中已知失败的依据，影响的因果解释仍由实际看图判断。私人来源用 `presentation.private_context` 核对样本、解释层级和本轮范围；检索关联不能证明已采用，更不能推导永久喜好。

明确的 A/B 相对选择仍用 `calibration record` 绑定两图、任务和比较标准，本项目默认账本为 `--ledger local-library/personal-calibration.json`。已有项目专用账本则配置其路径与适用题材，不复制出冲突记录。两类反馈都不能从机器评价推断；用户未说明具体原因就照实保留未知，模型解释另留在本轮复查。没有用户选择就保持未确认，不自动改写长期偏好。

## 成本边界

本 Skill 不触发工程回归、全库重新分析或额外图像生成。正常创作只做本轮输入、引用和交付校验；工程代码变更才按项目规则测试。复用当前有效观察；文件或需求改变时再核验。按小批次搜索和看图，批次容量不是参考总数或风格范围的上限；已有充分依据就停，扩展后仍不合适就进入 Copilot。历史反馈只取当前相关材料，提示词审查与必要修订仍保持有界；任何实际生图继续沿原许可及累计预算。
