# HEX 汽车 × Nano 提示词

本 Skill 可以单独导入宿主使用，不依赖 HEX 的 Python 运行时。它只负责“想清楚这张车图怎么拍，再写成 Nano 能读懂的提示词”；是否出图、出图后怎么检查返修，由宿主或完整 HEX 流程负责。

适用：单车外观静态照片（品牌图、生活方式图、爱好者胶片图、保身份改图）。不适用：视频、多车群像、座舱内饰特写、海报排版。

## 1. 先问清（最多 3 个问题，已答的不重问）

1. **车型与身份**：要保留某台真实车/现实车型（preserve，需要至少一张这台车的照片），还是不指定车型的开放创作（open）？改图一律按 preserve。
2. **风格模式**：`modern`（当代车/中国 EV，干净数码商业质感）还是 `retro`（60–90 年代经典车 + 胶片质感）？没回答或说“你定”就用 modern，并在方案里写明这是默认假设。
3. **有没有人，人和车是什么关系**：无人 / 倚车、坐、开门、取物 / 身体接触车身。没回答就按用途选一种，不擅自加群像。

另外确认 Nano 的具体型号（Pro、2.1、2、2 Lite 或旧版），以界面上的模型名为准；型号差异见 `knowledge/model-prompts/nano.md`。

## 2. 先做摄影决定，再写字

按下面的语义槽位逐项决定，每项只写本题需要的内容：

| 槽位 | 要决定什么 |
| --- | --- |
| 车型 | 品牌车型或“虚构车型”；preserve 时写出必须保留的灯组、轮毂、字标、比例 |
| 关系 | 人车关系与瞬间；无人时写车与环境的关系 |
| 机位 | 景别、高度、角度、车在画面中的位置与占比 |
| 光 | 光源、方向、受光面、投影；车漆上那条连续环境高光从哪里来 |
| 色场 | 主色（≤2 个色相）、服装与环境如何呼应 |
| 介质 | 数码商业 / 胶片（具体胶片质感）/ 黑白 |
| 保留项 | 改图或参考生成时必须不变的东西 |

**构图和视线不写死，每题从下面挑一个**：

- 车在画面中的占比：建筑尺度远景约 20–35% / 中景约 40–50% / 近景特写不超过 60%。
- 人物视线：看向画面外的去处 / 看向车或手上的动作 / 看镜头（只有用途需要时）。
- 留白：干净天空 / 干净墙面 / 不留白（不做版面时）。

## 3. 两种模式的精简清单

### modern（默认）

- 车型准确，车漆至少一条连续、不断裂的环境反射高光，金属漆有层次而不是塑料平涂。
- 生活方式四选一：松弛（咖啡、看书、倚车）/ 轻奢（建筑、低饱和材质）/ 家庭（孩子、宠物、行李，允许笑）/ 户外（海边、山路、营地）。
- 有来源的光：一致方向的清晰硬影，或黄昏、阴天的大面积柔光。
- 主色不超过 2 个色相；用户没指定颜色时可用暖红、陶土或红橙色场，服装呼应环境色。
- 人车关系要有动作或视线去处，不是车展式站桩。
- 干净数码商业后期、自然肤色。

### retro（用户明确选择时）

- 60–90 年代经典车，车、服装、道具年代一致，不出现现代屏幕、LED 尾灯和现代车标。
- 胶片质感：细腻均匀的颗粒（暗部多于亮部）、柔和高光溢出、略抬起的褪色黑、中低饱和；或高反差黑白。
- 朦胧感要具名并且只选一种：前景遮挡虚化 / 浅景深 / 雾或尘 / 慢门拖影。
- 硬质日光与斑驳阴影，或窗边侧光；不用多灯棚拍。
- 编辑片要求：人和车有身体接触（躺、坐、倚、伸出车窗），表情冷或不看镜头，画面有大块近黑或清晰硬影。
- 人物偏离中心，或通过车窗、门框形成框中框。

两种模式都可以选用雾、尘、烟或织物装置做氛围，但不能遮住车型和那条连续高光。

## 4. 按 Nano 的写法输出

- 写成**一到两段自然语言**，按“用途 → 主体与关系 → 场景与构图 → 光 → 色与材质 → 介质”的顺序。
- 用**正向的目标状态**描述想要的画面（例如“背景是干净的浅灰混凝土墙”，而不是一串“不要……”）。确需排除时，最后**只写一句**，只列本题最容易出错的 2–3 项。
- 多张参考图要**分配职责**：例如“图1只提供车辆身份和车身结构，图2只提供光线和色调”。负责风格的图不能同时接管车型。
- 需要画面里的文字时，给出准确原文、位置和字形；不需要就不写。
- 提示词里的“4K”“16:9”不替代工具里的实际尺寸设置，比例和分辨率在出图入口设定。

### 新建（open）

```text
为[用途]拍摄一张汽车外观摄影。一辆[虚构车型的整体气质与车身形态]停在[场景]，[人物与动作/无人时的车与环境关系]。[机位与景别]，车约占画面[占比]，[留白位置]。[光源与方向]在地面投下[影子]，车漆上有一条连续干净的[天空/墙面]反射高光。主色为[≤2 个色相]，[服装/道具]与环境色呼应。[介质与后期质感]。
```

### 参考生成（preserve）

```text
图1只提供车辆身份：保留[车型]的前脸灯组、轮毂、字标和车身比例。图2只提供[光线/色调/构图方法]，不借用其中的车辆。把这台车放在[场景]，[人车关系]，[机位与占比]。[光]，车漆保留一条连续的环境反射高光。[色场]，[介质]。
```

### 保身份改图

```text
编辑图1中的这台[车型]，只把[车漆/场景/光线]从[原状态]改为[目标状态]。保留车身比例、机位、轮毂、灯组、字标和[本题其他保护项]。让新的[光影/反射]与车身曲面连贯，车漆上保留一条连续的环境反射高光。
```

### 继续上一轮

```text
基于上一张结果，只把[具体问题]调整为[可见目标]，保留[已认可的部分]。
```

## 5. 交付前自查（逐项写“满足 / 待改 / 看不出”，不打分）

- 车型准确：灯组、轮毂、字标、比例和真实车型一致，没有融化的徽标和多余门缝。
- 车漆上至少一条连续、不断裂的环境反射高光。
- 当前模式清单逐条核对；无人时人物项注明“不适用”。
- 提示词里的每张参考图都有且只有一个职责。
- 用户的硬要求（颜色、保留项、比例）没有被风格清单覆盖。

## 6. 局限

- 本 Skill 只产出提示词和方案，不保证某个 Nano 型号的实际出图效果；本仓库尚未做该 Skill 的成图对照测试。
- Nano 各型号、各入口（Gemini App、AI Studio、API、第三方）在参考图数量和编辑能力上可能不同，以实际入口为准。
- 不判断参考图的版权和授权；品牌官方图、他人作品只作方法参考，不作为可交付素材。
- 在完整 HEX 流程中，汽车入口对 `nano` 只支持 `prompt_only`（交付提示词）。
