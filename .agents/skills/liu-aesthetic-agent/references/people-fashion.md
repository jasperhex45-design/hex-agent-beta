# 人物与时尚静图：让具体关系服务本题

在静态人物摄影、服装视觉或其有界修改中按需使用。这里补充现有观察、Plan 与模型编译，不建立第二个导演、评分器或生成循环。绘画、海报、影片镜头沿自己的方法；有意的变形、磨皮、强光、朦胧和夸张先按用户目标判断，不用写实标准覆盖全部风格。

## 先选本题真正要看的东西

人物的状态、衣服的形与材料、人与场景的关系、形式上的冲击，可以有不同主次。让已选用途决定景别、裁切、观看距离和细节投入；不要默认全身平视、固定焦段、面部最清楚或必须避开镜头注视。

从参考里提炼关系时，仍区分身份、姿态、光线和风格的授权范围。只喜欢参考的色彩，不因此保留它的人物、服装和动作。

## 三组按需检查

### 人物状态与空间

只记录实见的脸向、视线、支点、接触、遮挡及衣料张力。需要写实可信时，检查身体如何获得支撑、手与衣物或道具是否实际接触、遮挡与前后关系是否自洽。只列本题关键处，不把一套解剖检查机械塞给每个镜头。

这些关系可能技术上都正确，人物仍然显得拘谨或画面无重点。因此还要回看姿态是否支持所要表达的状态；不能用“手没有错误”代替“人物表现成立”。没有原图或看不清，就保留未知，不推断人物的内心经历。

### 皮肤、衣料与环境的光色关系

明确各类表面怎样回应光，而不只是列灯光、服装与背景名称。检查背景的反射或吸光是否影响主体，肤色、衣料高光和环境色是否共同支持本题。人物与背景既可以分离，也可以有意融入；不一律压暗背景、提高对比或降低饱和度。

肤质随景别和修饰用途处理：看不见的微细节不必强加，远景的体积与明暗过渡比逐个毛孔更重要；美容修饰也有其用途。不能把更白、纹理更多、完全无瑕或一律拒绝磨皮当成通用质量标准。

### 修改的收益与代价

如果用户只否定肤质或衣料表现，保留已经成立的身份、姿态、服装、构图与场景。只在真实授权的范围内改变对应因素，必要联动也要符合原 allowed_operations；不以调色为名重布光，不因修改皮肤重新设计脸形或身材。

把“看到了什么”和“猜测为什么”分开。不能仅凭成图断言一定是提示词、采样或底模的问题；复用 HEX 已有的分层诊断，缺证据时记 unknown。

## 接回 HEX 的原有记录

采用的关系写进现有 `choices.action/cooperation/tradeoff`，相关的可见成功与失败条件写进 `checks`，保留全部真实用户硬要求。原有字段够用，不再维护一份独立视觉规格。

编译只表达已采用的决定，不把本页所有检查项复制到最终提示词。模型卡与真实入口决定参数、负面语法和参考图用法；人的姿态或肤质方法不绑定某一宿主、操作系统或模型品牌。未知后端保持未知。

若确需比较两种拍法，尽量保持人物、服装、场景事件和光源关系一致，只检验本次提出的一项差异。用户明确要重设整体方向时不强行固定这些变量。提出方案不等于获准额外生成；真实调用仍沿原预算。

独立评审继续使用原流程，不向首评注入作者的辩护。程序接通、提示词写到、局部检查通过，与整体审美改善分别报告。

## 来源与验证边界

本页为 HEX 针对人物静图的原创方法归纳。对本机摄影、制作设计与结构审查 Skill 的审查帮助定位了缺少的检查粒度；未复制其脚本、完整协议或默认风格，也不要求用户安装这些外部 Skill。原有 Skill 保持独立，私有材料的公开复制需另核授权。

当前只有方法接入与工程回归依据，尚无本轮人物实图对照结果。新生产任务的 `people_method_version=1` 让相关规则进入已有观察、设计和编译阶段；旧任务缺少该标记时保持原方法，不读旧图反推已完成训练。指导方式可直接按本页完成判断，无需 Python 或 Codex CLI。
