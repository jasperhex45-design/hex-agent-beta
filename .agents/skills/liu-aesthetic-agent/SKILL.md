# HEX 通用创作方法

使用当前工程 `AGENTS.md` 与 `CODEX_START.md` 的唯一执行、完成和恢复流程。本 Skill 保留通用设计方法，不另建任务或合同。新任务经统一入口准备，已有任务先查真实状态；已生成首图仍需完成本题检查，不沿用旧“首图返回即结束”的默认。

## 1. 在任务指导之后理解与设计

先保存最小 brief 和真实消息来源，再准备任务。读取本题 `HOST_TASK.md`、`creation-instructions.md`、`production-context.json` 与 `packet.json` 后形成 Need；刷新后才根据当前材料形成 Plan；取得目标模型编译输入后才写完整提示词。保留“HEX 指导 → 宿主取舍 → 具体落实”的简短记录，不用后验 preflight 冒充 HEX 已指导创作。

默认离线 Need 是草稿，宿主按真实原话整理目标、主次、必须保留、允许改变和未知项。硬限制用 `constraint_evidence` 绑定来源，自主场景、构图与方法保持提案，不先填入最小 brief 冒充用户要求。先通过 `direction_review` 判断意图；模糊时在找图和设计前用 Copilot 问清最影响方向的感受、用途或偏好，不把用户限制在预设风格列表。已明确或已委托的内容继续，不让用户选焦距或技术模板。

实际 Need 后读取本题有限知识候选，核对版本、范围和职责，沿原 `choices.core_knowledge_ids` / checks 采用，允许零采用。无检索依据写 `basis=agent_hypothesis` 和空机制引用；不得伪造卡片。私人经验、旧反馈与模板不自动进入新任务，除非当前真实策略和授权已明确支持。

## 2. 必要素材与真实观察

`open_creation` 的用户输入可只有文字，含义是不要求保持参考身份，不是免除研究；`reference_transfer` 要亲见相关原图；`local_edit` 必须有真实编辑输入。缺必要身份素材不能改称开放创作，身份图不好看不代表可以换人或车型。未知焦距、灯具、位置或尺寸不冒称测量事实。

用原 `add-reference` / `observe` 绑定真实文件、职责、出处和观察；使用当前生成的参考 schema。不可见写 `seen=false`。评价参考带 `evaluation_only`，反例与评价图不上传给生成工具。观察不是上传授权，参考角色和素材顺序要保留；新增参考改变摘要后重新绑定设计。

新任务在 `Need.visual_research` 中选择研究路线。开放目标、明确研究请求或已拒绝方向走 `study`，按 [设计研究](references/design-study.md) 实际看作品，说明采用或舍弃怎样改变本题决定；检索关闭或零采用知识不能免除此步骤。用户已给定视觉方向或只做有界局部修改，可选 `specified_direction` / `bounded_edit`，用真实用户的来源和原话解释；用户明确禁止研究才可据原话选 `user_waived`，如实记为跳过。不能由宿主先编一个具体场景再自证无须研究。

用户说“这种画风／摄影风格”时，提取绘制、摄影、光色和组织方法；角色、服装、道具和原布局不自动进入新题。研究参考可为 `evaluation_only`，不要求上传；用 `choices.reference_uses` 关联真实观察、采用或舍弃依据与相应检查，不以链接或文字介绍冒充看过作品。

## 3. 把意图落实为有效画面

沿现有 Need / DesignPlan / choices 设计；静态图 `narrative=null`。根据用户目标和实际参考做审美选择，提案有比较价值时用现有 `creative_directions` 记录，不要求固定数量或先凑风格菜单。不确定就研究不同来源；仍无合适案例或需要用户偏好才能判断时，用 Copilot 共创，再形成一个有效方案，无须为每个提案生图。已指定方向或局部修改不无故重开创意；保留用户已认可的关系与风格强度，不用“增强张力”重做范围外内容。

从主体关系、空间与尺度、动作、视觉重心、光影、色彩及媒介中选择真正有用的手段。写明具体动作、相互支持或冲突、必要代价与可见失败条件；“高级”“电影感”不是动作。方向尚未成立就回到设计，纹理加细或局部提亮不能代替整体表达。

`spec.locked_facts` 保留 `need.must_keep`；operations 不越界，evidence_targets 与 checks 对应。保留身份、数量、精确文字、画内与画外区分、范围分母和遮挡关系。允许戏剧性、强色、颗粒、模糊或高密度，只判断是否服务用户目标；均衡不等于平均，不能把低饱和、纪实或无瑕当通用标准。

## 4. 完整模型编译与真实执行

先保存当前 Plan，再 `prepare-compilation`，读取真实 `compilation-input.json` 后为实际目标写完整正文和 adaptation。保留来源、动作覆盖、约束对应与上下文绑定；中英文表达都保持等义关系，不因模型不同而改变共同设计，也不固定“某模型必写长段”。

保留模型版本、正文覆盖、摘要与实参核对，执行 `preflight`。结构和片段出现不证明语义或美感。未知能力记 limitations / `not_controlled`，不加不存在参数或悄悄删需求。接口细节按需读 [模型适配](../../../docs/MODEL_ADAPTATION_AND_VALUE_20260926.md)。

成图／编辑任务沿本题有效许可执行 `authorize-generation → dispatch → 实际工具／执行器 → record-result`。原样使用 dispatch 的 request.arguments；立即保存真实图片、实际参数与回执。失败、pending 和 unknown 如实记录；未知只查原编号，不重复生成。必要工具不可用就说明具体缺口，不旁路执行后冒称 HEX 已验证。

## 5. 检查、有限修改与完成

原图可以先预览，但必须继续当前统一流程要求的文件、文字和视觉检查。画内文字明确要求时从冻结 checks 派生 OCR 要求；无文字要求不启动 OCR。视觉评审实际看本题候选，记录具体标准、观察、失败和未知；对象齐全、结构正确等基础可用性与情绪、主次、表达效果分开判断，不将基础检查满分称为审美满分，也不以机器自评代替用户接受。使用 `CODEX_START.md` 的统一完成门禁，提示词导出或首图返回都不是完整完成的替代凭证。

局部编辑绑定真实父图、新反馈和 change_scope / preserve；通过 `refresh --out` 建关联版本，必要时传真实 `--edit-reference` 和 `--parent-request-id`。随后重新观察、编译和 preflight。旧预算耗尽时只有已存在的新许可才可用 `grant-native-revision` 绑定；不清旧账、不另开独立任务绕过限制。

单父图、蒙版与软合成方法分别见 [Qwen 单父图](../../../docs/HEX_QWEN_SINGLE_PARENT_EDIT_20261007.md) 和 [蒙版编辑](../../../docs/HEX_QWEN_MASKED_EDIT_20261007.md)。原画布、父图摘要、保护蒙版和实际节点按当前路线核验；保护像素通过不等于身份、姿态或视觉质量成立。未接入控制就写缺口，不能称已保护。

同一路线连续两次出现相同可见失败且没有新证据、假设或控制输入时停止该路线，不靠换 seed 或加长提示词自动续图。保留当前失败、可用替代方案和缺失输入；任何新调用都沿已有权限与累计预算。用户明确停止时保存真实来源并 `stop-generation`；普通暂停用原 status/resume，不伪造用户停止。

## 6. 反馈和交付

把明确接受、拒绝、局部认可或相对偏好绑定真实图片、合同和原话。相对偏好用原 `record-feedback --decision relative_preference`，保留比较对象和每次独立消息；不拼接原话，不自动登记最终接受。来源和内部图号由宿主维护，不让用户填写 ID。

双模型比较冻结共同需求与各自完整正文，每个模型的独立首图按当前许可计数，不以第一张输出改写第二张；相对喜欢不触发自动补图。评估设计流程时，共同输入保留真实用户目标，不先把待比较的创意选择替两条路线做完；仅固定场景测试时明确其范围。报告保留整体结论和不利分项，不以单项占优宣称整体获胜。从比较结果续改时绑定实际选中的父请求，默认继承其模型，有真实来源才改目标。

交付实际产物、统一执行状态和简短设计说明。`design-explanation.md` 中的预期与已观察收益分开；只有完成检查通过才说完整流程已完成。没有用户最终判断时保持未记录；工程通过、工具成功、视觉检查与用户接受分别说明。
