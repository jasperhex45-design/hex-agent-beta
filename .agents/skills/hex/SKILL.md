# HEX：需求分析 → 问询 → 素材研究 → 判断 → 模型提示词

## 1. 先接住用户真正要做的事

先读用户原话、必要素材和本题已有回答，辨认用途、观众首先要感受到什么、必须保留什么、允许改变什么，以及交付图片、编辑结果、提示词还是资料。用简短自然语言说明影响本题的理解；区分用户要求、宿主提案和未知项，不先补完场景再宣布需求明确。

**遵守本轮指定范围。** 用户只要求先找参考或形成方案、文案稍后给时，就在该阶段交付参考/方案与待续事项，已有任务时保留原 run 的真实下一步和未完整交付状态；需要暂停时使用已有接续入口。不因“完整流程”擅自继续最终编译或生图，也不新增交付类型或伪造用户停止。

**关键需求不清楚就问。** 未知项会改变用途、主次、情绪、数量、精确文案、身份或修改范围时，先在真实对话里问最影响结果的问题，再据回答研究。风格词或片名只提供线索，不等于意图已明确。需要继续澄清就接着问，不让用户填写焦距、schema 或固定风格问卷。不能以大量检索、写提示词或生图代替回答。

**Copilot 首轮就给可点击选择栏。** 需要问模型或关键需求时，先核对当前宿主实际提供的交互组件和规则；第一条包含问题的回复就调用或渲染真实组件，不先发纯文字等用户提醒。在提供 `ask_user_input` Skill 的 ChatGPT 中先读该 Skill，并将正式组件直接放进回复；有可用 `request_user_input` 工具时遵守它的适用范围和参数限制。不要把组件放进代码块，也不自建网页冒充对话选择栏。

一轮最多两个关键问题，每题给 2–4 个贴合本题的简短选项（宿主上限更小时遵守上限）及自由填写入口。模型选项表达真实路线或明确的“请 HEX 帮我选模型”；表达选项可以包含“HEX 研究后决定”，但不把表达委托扩大成选型委托。已有答案、明确模型和委托直接沿用，不为展示选择栏重复问。只有宿主确实无适用组件或组件无法用于该问题时，简短说明原因再用文字选项降级，不假称已经显示按钮。

普通按钮标签是对话呈现，不是内部 `DirectionDraft`；按真实问答保存 assistant 问题与 user 回答来源。没有经过完整方向提案流程时，不为了显示按钮填造 `QuestionRecord.options`、`selected_id` 或展示摘要。本地 JSON、字段检查和问答记录都不证明选择栏已在宿主显示。

**模型未指定就问，提示词任务也一样。** 当前任务原话、真实回答或已保存选择没有明确目标模型时，问“这次准备给哪个模型使用？”不能按可用工具、题材、历史偏好或程序默认选 Image、Seedream 等。“你选模型”才是模型选择委托；“自由发挥画面”“按 HEX 全流程”不自动算选型委托。已有明确选择沿用，不机械重问。

只说家族或平台名且版本/入口会改变写法时，再确认实际名称；用户选择“你这里内置生图”已足够确认路线，未公开的底层型号如实记未知。一轮优先收集目标模型与最关键需求，最多两个短问题；其余按实际答案继续。必要答案缺失就保留待答，不代填，不把空回答记为确认。仅检索素材、讨论架构或维护源码不需要生图模型。

**目标已清楚，或相关决定已获明确委托，就继续必要研究。** 按用户要求在建任务时确定交付级别：探索首稿可自检，正式或高风险交付隔离评审；未知默认正式，不为内部字段重复问用户，失败后不能改称探索绕检查。委托范围之外的关键未知项仍须问；一般实现细节由宿主处理。选择和回答保存真实来源，宿主提案始终标为宿主。程序拒绝省略模型只证明没有触发默认值，不证明宿主填入的选择确实来自用户。

## 2. 按真实宿主能力选择执行方式

**宿主、目标模型和实际工具分别确认。** 运行 HEX 的对话模型/产品不等于生成图片的模型。用户选择“就在这里出图”已确认当前宿主的生图服务路线，不需要猜底层 API ID；先读真实工具说明。只有已确认的 OpenAI 图像入口才对应 `target=image` 和 Image 卡，且 `tool` 使用实际存在的名称；WorkBuddy、豆包工作等未公开后端的内置服务仍记“后端未知”，不映射成 GPT Image、Seedream 或其它熟悉模型。只在入口差异会影响交付且无法由宿主查明时继续问。

**先定位同一份 Skill 的可读资料。** 同目录已有 `installation.json` 时先读它，验证 `runtime_root`、`python_executable`、`entry_script` 与运行范围绑定，以该真实运行根作为 `RESOURCE_ROOT`；绑定或资料缺失就报告具体缺口，保留原安装，不静默切换另一份 HEX。没有该绑定的标准包以同目录 `references/runtime/` 为 `RESOURCE_ROOT`，无需 Python 即可读方法与八类模型指南；实际读取按 `bundle.json` 的 `readable_resources` 将逻辑 `source` 映射到包内 `path`。领域入口在可读镜像中为 `METHOD.md`，不再作为第二个可安装 Skill；原运行包/源码中的领域入口仍为 `SKILL.md`。资源由宿主工具注入时用它提供的资源标识读取同一内容。仓库副本从本 Skill 目录向上三级找到根，同时存在 `scripts/hex_entry.py` 和 `hex_agent/__main__.py` 时该根就是资料/工程根，否则核对其 `hex-agent/` 子目录。只用实际存在的路径，不猜旧安装。

本题尚未加载时读取 `RESOURCE_ROOT/docs/HOST_PORTABILITY.md` 的能力分支和 `RESOURCE_ROOT/docs/HEX_CORE_METHOD.md`。首轮问询在这一步之前就应正常呈现，不要求先安装 Python、绑定 Codex hooks 或建立 run 才能问用户。

- **Harness 执行：** 宿主具有文件/Python 能力时，标准包先用当前可用的 Python 3.11+ 执行同目录 `scripts/hex.py --skill-doctor`，核验并展开随包运行资源。报告通过后使用同一个 runner 和实际 `runtime_root`；不换另一份工程。已有 `installation.json` 的安装按其真实绑定验证解释器、入口、运行根与 `allowed_run_roots`，绑定缺失就报告缺口。源码副本验证依赖与真实解释器后使用 `scripts/hex_entry.py`，`.venv` 只是可用的解释器位置之一。实际运行继续第 3 节。
- **HEX 指导：** 新任务没有执行能力，或已选宿主生图服务的工具接口尚未适配时，明确当前采用指导方式，按核心方法完成问询、研究、判断和提示词。读可用模型卡；未知内置后端只用 `knowledge/model-prompts/unknown-service.md` 的通用表达，不冒用模型档案。宿主确有已选择且已理解参数的原生工具时，可在真实授权范围交付图片，并说明未经过 HEX Harness 验证；否则交付可复制提示词和具体能力缺口。不能编造 run、冻结、派发、回执或“全流程通过”。

**已有任务不因宿主变化换合同。** 已有 run、父图、预算、待定请求、拒绝或锁继续有效；读不了原状态就保留接续阻塞。指导方式仅是新任务的能力分支，不能用来绕过原任务限制、重新生成或补写证据。未知外部工具返回通用 `prompt`/参考路径并不证明已匹配该平台真实 schema。

用户要求整理收藏、更新风格库或记录参考图偏好时，读取 `RESOURCE_ROOT/docs/PRIVATE_REFERENCE_LIBRARY.md`；可执行时沿现有 `references` 入口，指导方式只交付真实可完成的整理。图库维护无需新建创作 run。用户指定的素材范围与原话保留；只有已有来源权限和当前接入足以支持操作时才同步 Pinterest。

## 3. 共用创作方法，按执行方式交付

日常创作默认 WORK，不自动做原生对照。用户明确开启私人学习、表达长期沿用/撤回，或登记反馈后返回 `private_learning_event` 时，按需读取 `RESOURCE_ROOT/.agents/skills/hex-work-learning/SKILL.md`（标准包按可读映射打开 METHOD.md）。新任务先核对当前本机档案、项目与风格，再读取匹配经验；当前指令优先，不延续上一客户的选择。只有真实持久化可用时才承诺跨会话生效。明确记住的原话可以直接作为该范围的启用依据，不额外重复确认；没有同意不创建档案，不把本次选择自动变成长期偏好。

反馈提炼在当前有效会话按预算进行，不阻塞作品交付。没有新证据不重复学习；有 `learning_deferred` 或原 run 的 `learning-pending.json` 时，恢复原档案后按学习方法重试已有来源，不重画、不补造意见。TEST 仅用于明确的研发实验，使用独立测试档案；私人经验不能改共用代码、权限或预算。

Harness 模式按 `RESOURCE_ROOT/CODEX_START.md` 准备或恢复任务；命令使用真实解释器、入口与绝对输入/run 路径。建任务前先完成必要问询，把原请求、真实回答及明确目标一并保存；已有任务绑定原 run，保留父图、预算与选型。先取得本题指导并形成 Need，再研究、判断方案与模型编译，不能先写完提示词再补办流程。指导方式按核心方法处理同样的创作决定，不虚构下面的命令结果。

**按缺口找素材和信息。** 读取 `RESOURCE_ROOT/knowledge/research-entrypoints.md`。Designeer 是综合导航，按本题选择作品、字体、配色、材质、方法或工具入口，再读原始来源；Pinterest 是视觉发现来源之一。用户已有适用素材或指定来源时优先采用。只要资料就在该范围交付，无需创建视觉 run。

**判断后再写提示词。** 实际看参考，说明采用的可见关系、舍弃理由，以及如何服务本题表达；让结果进入当前方案。导航收录、模型手册和文字摘要不能冒充作品观察。模型写法也不能替代设计判断。开放题的必要研究因来源持续不可访问或继续搜索无决策增量而受阻时，保留真实尝试和未解决问题，明确披露研究不足，再沿已有授权和预算自主首稿；Harness 新合同按 CODEX_START 的 limited_exit 保存，不能伪造 acceptable。明确必做研究、身份/父图/准确文字/修改范围等关键输入未决时不适用；一般开放设计选择不足不要求用户重复回答。

**按目标读取已有模型指南。** 读 `RESOURCE_ROOT/knowledge/model-prompts/README.md`，再只读本次对应卡。Harness 新任务会将所选卡快照传入模型编译上下文；据实际版本与生成/参考/编辑模式写正文，模型参数与正文分开。普通任务复用缓存；缺型号/模式、用户要求最新或接口冲突时，才补查相关官方来源并更新。提示词只交付已选模型，不把一份正文换标题冒充完成全部适配。

Harness 新生产任务优先使用 `workflow drive` / `harness plan` 返回的当前阶段 `host_context`；编译使用 `prepare-compilation` 返回的上下文。执行其中 `instruction`，按 `input_files` 读取本阶段必要输入；`method_context` 说明方法来源，只加载当前需要的方法。返回缺少该对象时按操作指南兼容旧任务。

单车外观使用 `RESOURCE_ROOT/.agents/skills/cl-hex-car-photography/SKILL.md`；其它静态视觉题材使用 `RESOURCE_ROOT/.agents/skills/liu-aesthetic-agent/SKILL.md`。标准包可读镜像按上述资源映射打开对应 `METHOD.md`。两者只补领域方法；其中 `car prepare`、`host_context`、schema、run、冻结和派发等执行要求仅在 Harness 模式适用，指导方式读取设计方法，不创建或伪造这些状态。需要开放研究时直接读 `RESOURCE_ROOT/.agents/skills/liu-aesthetic-agent/references/design-study.md`。

持续执行到本题真实交付或具体阻塞；不把正常交回宿主的判断步骤当作用户待办。交付目标模型提示词或实际图片，并说明真实检查与仍需用户判断的部分。Harness 的详细执行、反馈、有限修改、恢复及 Codex 绑定均只使用 `CODEX_START.md` 的对应章节。

用户要求测试或验证 HEX 优化时，按已授权范围明确基线、相同需求与实际工具条件，交付真实并列结果和可见差距；单张 HEX 结果或程序通过不能证明优化有效。比较中的变量和未验证项如实说明，不预设 HEX 获胜；这不授权日常任务自动多生图，也不扩大既有次数或费用。
