# 知识与模型档案

## 当前任务只读必要部分

| 内容 | 用途 |
| --- | --- |
| `knowledge/core` | 有范围的表达提示与知识种子 |
| `knowledge/design` | 带条件、依赖和代价的设计方法 |
| `knowledge/models` | 目标模型的写作与通道适配信息 |
| `knowledge/art_structure` | 有来源的空间组织研究索引 |
| 当前任务参考与观察 | 本次真正看过的图片、职责与可见证据 |

知识种子和设计假设不代表经过视觉验证，也不是所有人的审美偏好。来源、状态、版本与适用范围随条目保留。实际条目数量由 `python -m hex_agent validate` 读取，模型档案由 `python -m hex_agent models list` 查看。

## 参考怎样进入创作

先判断本题缺少哪类依据，再通过宿主实际可用的搜索、看图或本地文件工具取得它。身份、风格、光线、编辑输入和评价参考分别承担当前职责；链接或名气不证明看过图，也不证明使用者喜欢。

宿主通过当前 `add-reference` 与 `observe` 保存真实材料和观察，再关联本题的设计取舍与检查。参考更新会使受影响的观察、方案或编译失效，按当前任务状态重做必要部分。具体接口见 [来源输入](SOURCE_AND_REVIEW_INPUTS.md) 与 [CODEX_START.md](../CODEX_START.md)。

本地检索只提供候选，允许零采用。可选原生语义环境缺失时记录实际降级，不声称已完成向量检索。其配置见 [运行环境](HEX_WINDOWS_WORKFLOW_20261007.md)。

## 方法与模型更新

维持用户的事实、意图与硬限制，再调整对应模型的表达方法。模型档案的内部版本和外部模型版本分别记录；工具标签、档案 ID 和真实调用 model ID 也分别核对。档案存在不表示该生成 API 已连接。

新规则先作为有范围的候选，用实际任务与结果比较；旧页面变化或模型宣传不证明规则有效。当前使用者的选择只作用于有依据的任务范围，不将作者过去的个人习惯作为所有测试者的默认。

维护者在开发库校验修改、运行相关回归，再用独立实际案例确认效果。内测用户不必运行工程测试或读取整库。

## 反馈与来源

记录原需求、参考职责、实际正文、调用模型、真实结果与使用者反馈，区分暂时保留、相对喜欢和最终接受。一次改图成功不等于训练了模型权重，也不自动形成永久偏好。

私有任务、偏好库和下载素材保留在本机，不随内测源码提交。第三方方法和材料的来源及许可见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) 与 [来源说明](SOURCES_AND_PROVENANCE.md)。
