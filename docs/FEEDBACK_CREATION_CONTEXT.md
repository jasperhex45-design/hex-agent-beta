# 明确反馈与创作依据

本改动解决三个运行时断点：生产策略关闭经验检索时，明确用户反馈也被遗漏；编译上下文缺少部分机位、检查和参考依据；旧生成图的复盘可能被当作完成作品学习。它不定义统一摄影风格，也不把工程检查当成视觉提升。

## 用户反馈进入下一次创作

`record-feedback` 保存接受、拒绝、正向评价或双图相对偏好后，CLI 自动登记原任务。`calibration record` 自动登记成对记录。已有 Python 集成可使用 `user_feedback_context.register_run` / `register_pair` 登记原来源，不复制或重写评价。

登记只保存来源位置和适用范围。每个新任务最多召回三条相关记录（配置最多六条），保留用户原话、比较对象、图片摘要和决定类型。新任务在 `make_packet → refresh_packet → design_input / compilation_input` 中冻结并使用这些记录。模型适配上下文和证明包含同一冻结记录。

私人图库和未经验证经验继续受原生产策略控制。用户反馈不是知识卡通过、最终接受、上传许可或新增生图许可。当前需求覆盖旧反馈；相对更好不代表已接受，共同缺陷仍保留原话。

默认范围结合题材与领域，排除通用质量词。成对账本中的 `hybrid` 只在原评价明确写出人车复合题材时映射到相关人物／汽车任务。宿主可用 `--task-term` 和成对记录的 `--recall-domain` 进一步限定真实范围，不能用这些字段发明长期偏好。

本地来源索引是 `local-library/user-feedback-context.json`，不随 Git 发布机器路径。没有索引的新安装不宣称读到了别处的历史。迁移已有反馈时登记该机器上真实存在、可验证的来源；不扫描全盘。`--no-style-context` 继续关闭本题私人图库和用户反馈召回。

## 研究证据与创作决定

新准备的任务使用 `creative_context_version=1`。需要研究时明确 `Need.visual_research.evidence_requirement`：

| 职责 | 能支持的判断 | 所需证据 |
| --- | --- | --- |
| `feedback_review` | 对旧候选和用户评价的复盘 | 实际观察与用户指定的复盘范围 |
| `visual_reference` | 借鉴作品的可见关系 | 实际观察、来源类别与作品绑定 |
| `professional_analysis` | 学习作品及专业解读 | 同一作品像素、来源与署名、实际观察、保存的解读摘录 |

每项 `RefFinding.source_kind` 如实选择 `generated_candidate`、`user_reference` 或 `external_work`。生成候选不能满足视觉作品或专业分析职责。

专业来源通过现有 `attach-research` 保存到 `research.sources`，包含 `url`、`title`、`author`、`excerpt`、`reference_ids`。观察中的 `professional_source_url` 与 `professional_excerpt` 必须引用这个记录，并指向同一参考作品。代码只验证这些记录的绑定关系；宿主仍需实际查阅、看图和判断，不凭字段声称专家身份或学习效果已获验证。

模型编译输入保留 `camera`、`reading_order`、表达目标、每项 choice 对应的检查以及已观察参考的采用／舍弃依据。这些内容进入编译摘要；修改依据后旧编译不能继续冒充当前方案。具体光线、姿态和机位由本题表达决定，不通过禁用关键词统一所有题材。

## 恢复与失效

历史 packet、请求快照、已完成结果与导出读取冻结反馈，不受今天的来源变化影响。新的设计、修订、编译、派发及执行器首次提交会重新核对已选反馈。撤回、记录变化或图片不一致时停止新的使用，按真实任务状态刷新或建立关联版本；不清空旧证据与预算。

`pending/outcome_unknown` 继续沿原请求核对，不因为反馈更新重发。自动登记失败时保留已经保存的用户评价，同时在 JSON 与 human 输出中明确报告，不能声称后继任务已能召回。

旧包没有新版本标记时保持原序列化和编译摘要，不在读取历史时静默迁移。实际视觉质量与用户接受需要另行观察真实成图；相关回归测试证明输入传递、来源绑定和恢复边界，不证明首图更美。
